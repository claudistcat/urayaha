# ロードマップ

URAYAHA は、ジョーク言語の見た目のまま、**小規模な実用プログラム・GUI アプリ・
簡単なゲームまで作れる汎用言語** を目標に育てています。

長期の最終マイルストーンは、**Linux カーネルを基盤に、ユーザーが触る部分の大半を
URAYAHA で構成したデスクトップ環境** です。独自カーネルは目標に含めません。
カーネル・ドライバ・既存の低レイヤ資産は Linux のものを使います。

---

## 開発の進め方

```
作る
 ↓
困る
 ↓
仕様を追加する
 ↓
また作る
```

**機能を増やすために仕様を増やしません。** 実際に URAYAHA で何かを作って
不足が判明したときに追加します。

これは反省から来ています。v0.2 の仕様書は机上で書かれた結果、識別子と数値が
字句レベルで区別できない、型注釈が数値と衝突する、EBNF とコード例が矛盾する、
といった実装不能な穴を抱えていました。経緯は
[docs/dev/spec-decisions.md](dev/spec-decisions.md) にあります。

ただし **「作る前から分かっている不足」は、発見を待たずに先に埋めます。**
一括リネームツールを書き始めて「rename が無い」と気づくのは、検証ではなく
予定調和です。

## v0.5 — 基盤の安定化

**終了条件: 既知の問題を直し、実用 CLI を書き始めるために明白に必要な
基礎能力が揃っている。**

### 標準ライブラリの底上げ

いま無いと実用 CLI が書けないものを埋めます。

| 領域 | 足すもの |
|---|---|
| 文字列 | substring / replace / trim / startsWith / endsWith / find / 大文字小文字変換 |
| パス(`プスン`) | join / basename / dirname / extension / absolute / mkdir / **move(rename)** |
| 日時(`フゥ～ンフゥン`) | format / parse |
| HTTP(`プルャウラウラ`) | method 指定 / request headers / status code / response headers |
| コレクション | キー関数つきソート |

**正規表現は保留します。** ログ解析には強力ですが、v1.0 に必須とは限りません。
まず通常の文字列 API を充実させ、それでも実用アプリで必要と判明したら入れます
([ADR-0003](dev/decisions/0003-regex-deferred.md))。

### 既知の問題の整理

- 引数ひとつひとつの型検査(現在は個数のみ)
- ループ本体で作ったクロージャが Cell を共有する件
- 複合代入(`+=` 等)を添字・メンバに使うと対象式が 2 回評価される件
- 整形器が演算子まわりの空白を触らない件
- 発行経路が無い診断コードの整理
- ドキュメントと実装の差分(各リファレンスの `要確認` 節)

## v0.7 — バイトコード形式の刷新と回帰テスト

### `.urab` を安全な自前形式にする

現在の `.urab` は Python の pickle です。読み込むだけでホストの Python コードが
実行されうるので、**一般配布より前に置き換えます**
([ADR-0002](dev/decisions/0002-urab-format.md))。

互換性を保証しない方針と、安全な形式にすることは両立します。

### 言語レベルの回帰テスト

`.ura` を入力として、**stdout / stderr / 終了コードまで含めて** 固定します。
変数・関数・再帰・クロージャ・List / Map・map / filter / reduce・Optional・
Result・例外・match・struct・import・ファイル I/O・JSON・HTTP・文字列補間・
CLI 引数・診断メッセージが対象です。

## v1.0 — 安定版

**定義: URAYAHA だけで小規模な実用 CLI アプリを安定して作れる。**

判定の目安は、**Python コードを書かずに、URAYAHA だけで実用 CLI アプリを
最低 3 本作れること** です。

必須条件は、言語コア・型システム・VM が安定していること、File / JSON / HTTP
などの基本ライブラリが使えること、診断が実用レベルであること、formatter /
checker / build / run が安定していること、十分な回帰テストがあること、
インストールが容易であること、ドキュメントが仕様と一致していること、そして
URAYAHA 製の実用アプリが複数存在することです。

## v1.x — 実用言語としての拡張

既存コードとの互換性を維持しながら広げます。標準ライブラリの拡充、Path 操作、
日時処理、Unicode と文字列処理、subprocess、networking、コレクション強化、

「CLI 用途なら普通に使える」状態を目指します。

## v2.x — GUI アプリケーション

**URAYAHA だけでデスクトップ GUI アプリを作る。**

デジタル時計、ストップウォッチ、タイマー、電卓、メモ帳、JSON ビューアが
最初の代表アプリです。Window / Label / Button / Text Input / Layout /
Event Callback / Timer / Event Loop が必要になります。

ホスト実装は内部に隠蔽し、URAYAHA 側にホスト固有の API を露出させません。

**イベントループはホストが所有します**([ADR-0001](dev/decisions/0001-event-loop-ownership.md))。

---

## v3.x — 描画とゲーム

**URAYAHA で小規模な 2D ゲームを作れる。**

Snake、Pong、ブロック崩し、簡単なシューティングが目標です。Window /
フレームループ / デルタタイム / キーボード / マウス / 2D 描画 / 画像 /
フォント / 音声 / 当たり判定の補助が必要になります。

ゲームエンジンを自作する必要はなく、既存のバックエンドを URAYAHA Runtime から
ラップして構いません。ここでも **フレームループはホストが所有します**。

## 最終マイルストーン — URAYAHA OS

Linux カーネルを基盤とし、ユーザー空間の主要部分を URAYAHA 中心で構成した
Linux 環境。Linux そのものの再実装は目的ではありません。**起動後にユーザーが
触る環境の大部分が URAYAHA で構成されている** 状態が完成形です。

## Web 対応について

HTML / JavaScript / WebAssembly への対応は可能性として残しますが、現時点では
主要ロードマップに含めません。優先順位は CLI → GUI → ゲーム → デスクトップ環境
→ OS です。必要性が生じた段階で別途検討します。

## バージョニング

v1.0 以降は Semantic Versioning に近い考え方を採用します。

| | 意味 | 例 |
|---|---|---|
| PATCH | 互換性を壊さないバグ修正 | Lexer の不具合、型検査の誤判定、VM のクラッシュ、診断の改善 |
| MINOR | 互換性を維持した機能追加 | 新しい標準ライブラリ、新しい型、新しい CLI コマンド |
| MAJOR | 既存の `.ura` を壊しうる変更 | キーワードの意味変更、構文変更、型システムの非互換変更 |

`.ura` は v1.0 以降、同一 MAJOR 内で可能な限り後方互換性を維持します。
`.urab` は **バージョン間の互換性を保証しない内部形式** として扱います。
ソースは資産として残せますが、バイトコードは必要に応じて再ビルドします。
これにより VM 内部を今後自由に改善できます。

v0.x は仕様を固めるための開発期間なので、破壊的変更を許容します。

## 開発上の原則

```
表面: うさぎ
内部: 普通のコンパイラ設計
```

表面構文は可能な限りうさぎ語で維持し、処理系内部まで無理にうさぎ語化しません。

> **コードは鳴き声。構文はまとも。エラーは泣く。最終的には OS も鳴く。**
