# 診断リファレンス

URAYAHA の診断は、`[E2001]` のようなコード、見出し、ソースの位置、説明の順に表示されます。コードが同じでも、失敗した操作によって説明は変わります。このページでは各コードの代表例を示します。

診断と警告は標準エラー出力（stderr）に、`イヤッハー` による出力は標準出力（stdout）に出ます。以下の出力は実際の CLI 実行から採録しました。stderr を捕捉しているため、対話端末だけに出る起動バナーは含みません。出力末尾の空行だけを省略しています。

例は指定されたファイル名で UTF-8 保存し、プロジェクトのルートから実行してください。Windows の PowerShell では、先に次を設定します。

```powershell
$env:PYTHONIOENCODING = "utf-8"
```

`file.ura:12:15` は、ファイルの **10 進数で 12 行目、15 文字目**を表します。行と列は 1 から始まり、うさぎ数字の 4 進表記ではありません。下の `^` は該当する文字を指します。日本語など幅の広い文字には複数の `^` が使われます。

`E` はエラー、`W` は警告です。構文・名前・型の検査で止まる例の終了コードは 1、実行時に捕捉されず止まる例は 3 です。通常の警告だけなら 0 で実行を続けます。ただし `--strict-usagi` の W1006 は実行前に終了コード 1 で止まります。コードの分類と終了コードは別です。たとえば E3003 は型検査でも発生します。

## 詳細表示と `--debug`

`--debug` を付けると、エラーの見出しに `TypeMismatch` などの内部名が加わります。「ほしかったもの / きたもの」の詳細は、その診断に詳細情報がある場合に表示されます。現在の実装では、この詳細は `--debug` なしでも表示されます。すべての診断にこの 2 行が付くわけではありません。通常の警告表示には、`--debug` を付けても内部名は加わりません。

`debug.ura`：

```urayaha
ヤハ ヤハァ: プルッ = "ヤハ"
```

実行：

```console
python -m urayaha run debug.ura --debug
```

stderr（終了コード 1）：

```text
[E2001] 泣いちゃった！   (TypeMismatch)

debug.ura:1:15

    ヤハ ヤハァ: プルッ = "ヤハ"
                          ^^^^^^

ここに来るもの、なんか違うみたい…

ほしかったもの : プルッ
きたもの       : ワァッ
```

## 構文（E0xxx）

### E0001 — UnexpectedToken

見出しは「ワァッ！？」です。

その位置に置けない記号や語があるときに発生します。式として読めないトークン、代入できない左辺、名前付き引数と位置引数の混在、不正な公開宣言や分岐の並びなどが該当します。

`e0001.ura`：

```urayaha
)
```

実行：

```console
python -m urayaha run e0001.ura
```

stderr（終了コード 1）：

```text
[E0001] ワァッ！？

e0001.ura:1:1

    )
    ^

「)」、ここでは読めないみたい
```

### E0002 — MissingToken

見出しは「ワァッ！？」です。

必要な語や区切りが足りないときに発生します。括弧、`ハァッ`、文字列の閉じ引用符、コメントの `*/`、文字列補間の閉じ括弧、`.` の後の名前などが対象です。次の例は閉じ括弧がありません。ファイル末尾の改行後を指すため、位置は 2 行目になります。

`e0002.ura`：

```urayaha
イヤッハー("ヤハ"
```

実行：

```console
python -m urayaha run e0002.ura
```

stderr（終了コード 1）：

```text
[E0002] ワァッ！？

e0002.ura:2:1

「)」がないみたい
```

### E0003 — InvalidLiteral

見出しは「ワァッ！？」です。

数値や文字列のエスケープをリテラルとして読み取れないときに発生します。`ン・` の直後にうさぎ数字がない場合や、文字列末尾のバックスラッシュの直後で入力が終わる場合が該当します。

`e0003.ura`：

```urayaha
ン・
```

実行：

```console
python -m urayaha run e0003.ura
```

stderr（終了コード 1）：

```text
[E0003] ワァッ！？

e0003.ura:1:1

    ン・
    ^^^^

「ン・」のあとに数字(ン プ ル ャ)がないみたい
```

### E0004 — InvalidIdentifier

見出しは「ワァッ！？」です。

名前として読めない語や、メンバー名にできないトークンを使うと発生します。たとえば `.` の直後の数値、文字列、演算子はメンバー名にできません。

`e0004.ura`：

```urayaha
"ヤハ".ン・プ
```

実行：

```console
python -m urayaha run e0004.ura
```

stderr（終了コード 1）：

```text
[E0004] ワァッ！？

e0004.ura:1:6

    "ヤハ".ン・プ
           ^^^^^^

「ン・プ」はメンバ名にできないみたい
```

## 名前解決（E1xxx）

### E1001 — UndefinedIdentifier

見出しは「エッ…エッ…」です。

変数、型、メソッドの対象型、フィールドなどの名前が見つからないときに発生します。構造体にないメンバー、名前付き生成の未知のフィールド、モジュールから公開されていない名前へのアクセスも対象です。組み込み型の未知のメンバーは、検査時には E2005、実行時には E1001 になる場合があります。

`e1001.ura`：

```urayaha

```

実行：

```console
python -m urayaha run e1001.ura
```

stderr（終了コード 1）：

```text
[E1001] エッ…エッ…

e1001.ura:1:7

    イヤッハー(ヤハァ)
               ^^^^^^

「ヤハァ」って…なに？
```

### E1002 — DuplicateIdentifier

見出しは「エッ…エッ…」です。

同じスコープで名前を重複して宣言すると発生します。構造体のフィールドの重複や、組み込み型と同じ名前での型宣言も対象です。

`e1002.ura`：

```urayaha
ヤハ ヤハァ = ン・プ
```

実行：

```console

```

stderr（終了コード 1）：

```text
[E1002] エッ…エッ…

e1002.ura:2:1

    ヤハ ヤハァ = ン・ル
    ^^^^

「ヤハァ」、この中にもういるみたい
```

### E1003 — InvalidScope

見出しは「エッ…エッ…」です。

その場所では許されない操作をすると発生します。関数外の `ハァーッ`、ループ外の `ムリッ` と `イヤッ`、メソッド外の `コレ`、定数への再代入が該当します。

`e1003.ura`：

実行：


stderr（終了コード 1）：

```text
    ^^^^^^^^

ここでは ハァーッ できないみたい
```

### E1004 — UnknownModule

見出しは「エッ…エッ…」です。

文字列を使わない `これって…` に、存在しない標準モジュール名を指定すると発生します。文字列で指定したファイルがない場合は E3004 です。

`e1004.ura`：

```urayaha

```

実行：

```console

```

stderr（終了コード 1）：

```text
e1004.ura:1:1

    これって… ヤハァ
    ^^^^^^^^^

「ヤハァ」ってモジュール、知らないみたい
```

## 型（E2xxx）

### E2001 — TypeMismatch

見出しは「泣いちゃった！」です。

値の型が必要な型と合わないと発生します。型注釈付き変数の初期値や再代入、構造体のフィールド、真偽値を要求する条件、リストの添字、不適合な値同士の加算などが対象です。数値変換できない値や、乱数の境界に整数以外を渡した場合にも実行時に発生します。

`e2001.ura`：

```urayaha
ヤハ ヤハァ: プルッ = "ヤハ"
```

実行：

```console
python -m urayaha run e2001.ura
```

stderr（終了コード 1）：

```text
[E2001] 泣いちゃった！

e2001.ura:1:15

    ヤハ ヤハァ: プルッ = "ヤハ"
                          ^^^^^^

ここに来るもの、なんか違うみたい…

ほしかったもの : プルッ
きたもの       : ワァッ
```

### E2002 — InvalidOperation

見出しは「泣いちゃった！」です。

値にその操作を適用できないと発生します。数値以外への符号反転、計算や比較、呼べない値の呼び出し、列挙・分解できない値、添字を使えない値などが該当します。乱数の上下限が逆、比較できない値の並べ替えでも発生します。

`e2002.ura`：

```urayaha
-"ヤハ"
```

実行：

```console
python -m urayaha run e2002.ura
```

stderr（終了コード 1）：

```text
[E2002] 泣いちゃった！

e2002.ura:1:1

    -"ヤハ"
    ^

これにはマイナス付けられないみたい
```

### E2003 — WrongArgumentCount

見出しは「ワァ…」です。

引数の個数が許された範囲に合わないと発生します。関数や組み込みメソッドの呼び出しに加え、構造体生成の不足・過剰な値、実行時の分解代入で要素数が合わない場合も対象です。引数数の詳細は、位置表示とは異なり、うさぎ数字で出ます。

`e2003.ura`：

```urayaha
プルッ()
```

実行：

```console
python -m urayaha run e2003.ura
```

stderr（終了コード 1）：

```text
[E2003] ワァ…

e2003.ura:1:4

    プルッ()
          ^

もうちょっとほしいみたい

ほしい : ン・プ
きた   : ン・ン
```

### E2004 — InvalidReturnType

見出しは「泣いちゃった！」です。

`ハァーッ` が返す値が、関数に宣言した戻り値型と合わないと発生します。値を返す型の関数で値なしの `ハァーッ` を使う場合も対象です。

`e2004.ura`：

```urayaha
フゥン ヤハァ() -> プルッ ヤーッ

ハァッ
```

実行：

```console
python -m urayaha run e2004.ura
```

stderr（終了コード 1）：

```text
[E2004] 泣いちゃった！

e2004.ura:2:10

        ハァーッ "ヤハ"
                 ^^^^^^

戻すもの、なんか違うみたい…

ほしかったもの : プルッ
きたもの       : ワァッ
```

### E2005 — InvalidMember

見出しは「エッ…エッ…」です。

List、Map、String、Result にないメンバーを型検査で参照すると発生します。構造体の未知のメンバーは E1001 です。

## 実行時（E3xxx）

### E3001 — DivisionByZero

見出しは「泣いちゃった！」です。

除算 `/` または剰余 `%` の右辺が 0 のときに発生します。

`e3001.ura`：

```urayaha
イヤッハー(ン・プ / ン・ン)
```

実行：

```console
python -m urayaha run e3001.ura
```

stderr（終了コード 3）：

```text
[E3001] 泣いちゃった！

e3001.ura:1:11

    イヤッハー(ン・プ / ン・ン)
                      ^

これじゃ割れないヨ…
```

### E3002 — IndexOutOfBounds

見出しは「ワァァァァ！！」です。

リスト、タプル、文字列の添字が範囲外のときに発生します。リストへの添字代入も対象です。負の添字は末尾から数えた位置に直してから判定します。Map に存在しないキーの参照は `……` を返し、この診断にはなりません。

`e3002.ura`：

```urayaha
イヤッハー([][ン・ン])
```

実行：

```console
python -m urayaha run e3002.ura
```

stderr（終了コード 3）：

```text
[E3002] ワァァァァ！！

e3002.ura:1:9

    イヤッハー([][ン・ン])
                 ^

そこには何もないみたい
```

### E3003 — NullAccess

見出しは「ワァァァ！！」です。

`……` に対してメンバーや添字の読み書きをすると実行時に発生します。また、Any ではない Optional 型の値に `?.` を使わずメンバーアクセスすると、型検査時にも「「……」かもしれないみたい(「?.」がいるかも)」と診断されます。次は Any 型を通して実行時のエラーを再現します。

`e3003.ura`：

```urayaha
ヤハ ヤハァ: ナンカッ = ……
イヤッハー(ヤハァ.ン?())
```

実行：

```console
python -m urayaha run e3003.ura
```

stderr（終了コード 3）：

```text
[E3003] ワァァァ！！

e3003.ura:2:10

    イヤッハー(ヤハァ.ン?())
                     ^

「……」だったみたい
```

### E3004 — IOError

見出しは「泣いちゃった！」です。

読み込もうとした自作モジュールのファイルが存在しないと発生します。CLI に渡した実行対象が存在しない場合にも E3004 が出ますが、その場合の終了コードは 1 です。標準ライブラリ `プスン` の読み書きなどで処理される I/O の失敗は、通常は失敗した Result になり、直接この診断にはなりません。

`e3004.ura`：

```urayaha
これって… "missing.ura" -> ヤハァ
イヤッハー(ヤハァ)
```

実行：

```console
python -m urayaha run e3004.ura
```

stderr（終了コード 3）：

```text
[E3004] 泣いちゃった！

e3004.ura:1:1

    これって… "missing.ura" -> ヤハァ
    ^^^^^^^^^

"missing.ura" ないみたい…
```

### E3005 — NetworkError

見出しは「泣いちゃった！」です。

現在の実装には、このコードを発行する箇所がありません。したがって、E3005 を発生させる URAYAHA の最小プログラムと実際の診断出力は提示できません。通信の失敗をこのコードで表示すると考えないでください。

`プルャウラウラ.フゥン` と `.ヤハ` は、処理内で捕捉した通信の失敗を Result として返します。失敗した Result を `.なんとかなれーッ！()` で取り出して捕捉しなければ、診断は E3006 になります。`.ハァ?` は GET の Result の成功・失敗から真偽値を返します。

### E3006 — UncaughtException

見出しは「ワァーッ！」です。

`ワァーッ！(...)` で送出した値、または失敗した Result に対する `.なんとかなれーッ！()` が、どの `ダメだった…` にも捕捉されないまま実行の最上位まで届くと表示されます。どちらも同じ例外として伝わり、どちらも `ダメだった…` で捕捉できます。捕捉された場合、E3006 の診断は出ません。

`e3006.ura`：

```urayaha
ワァーッ！("ころんだ")
```

実行：

```console
python -m urayaha run e3006.ura
```

stderr（終了コード 3）：

```text
[E3006] ワァーッ！

e3006.ura:1:1

    ワァーッ！("ころんだ")
    ^^^^^^^^^^

ころんだ
```

失敗した Result から取り出した場合も、同じコードになります。

`e3006_unwrap.ura`：

```urayaha
ワァ…("ころんだ").なんとかなれーッ！()
```

実行：

```console
python -m urayaha run e3006_unwrap.ura
```

stderr（終了コード 3）：

```text
[E3006] ワァーッ！

e3006_unwrap.ura:1:22

    ワァ…("ころんだ").なんとかなれーッ！()
                                        ^

ころんだ
```

両方を捕捉する例です。catch の変数には送出した値が入ります。

`caught.ura`：

```urayaha
なんとかなれーッ ヤーッ
    ワァーッ！("明示的な送出")
ダメだった… -> ヤハァ ヤーッ
    イヤッハー(ヤハァ)
ハァッ
なんとかなれーッ ヤーッ
    ワァ…("Result の失敗").なんとかなれーッ！()
ダメだった… -> ヤハァ ヤーッ
    イヤッハー(ヤハァ)
ハァッ
```

実行：

```console
python -m urayaha run caught.ura
```

stderr（終了コード 0）：

出力はありません。

stdout：

```text
明示的な送出
Result の失敗
```

## 内部エラー（E9001）

### E9001 — InternalCompilerError

見出しは「ワァァァァァァァァァァァァ！！！！！」です。

CLI が `.urab` を読み込む際に、保存データを読み取れないと出ます。この例は URAYAHA ソースの構文では再現できないため、壊れたバイトコードファイルを作って再現します。

PowerShell で次を実行します。作業用の空のディレクトリで行ってください。

```powershell
[System.IO.File]::WriteAllBytes("broken.urab", [System.Text.Encoding]::UTF8.GetBytes("not bytecode"))
python -m urayaha run broken.urab
```

stderr（終了コード 1）：

```text
[E9001] ワァァァァァァァァァァァァ！！！！！

Urayaha VM Internal Error

broken.urab が読めないみたい
```

この例では診断コードが E9001 でも、終了コードは内部エラー用の 70 ではなく 1 です。実行時の再帰上限などでは内部エラーのバナーと終了コード 70 が使われますが、常に `[E9001]` が付くわけではありません。

## 警告（W1xxx）

### W1001 — UnusedVariable

見出しは「フゥン…」です。

宣言した変数を一度も参照しない場合に出ます。名前が `_` で始まる変数は対象外です。関数・型の宣言や関数引数そのものは、この未使用変数の警告の対象ではありません。

`w1001.ura`：

```urayaha
ヤハ ヤハァ = ン・プ
```

実行：

```console
python -m urayaha run w1001.ura
```

stderr（終了コード 0）：

```text
[W1001] フゥン…

w1001.ura:1:1

    ヤハ ヤハァ = ン・プ
    ^^^^

「ヤハァ」、一回も使ってないみたい
```

### W1002 — ShadowedVariable

見出しは「フゥン…」です。

内側のスコープで、外側の変数と同じ名前を宣言すると出ます。同じスコープ内の重複とは異なり、宣言自体は許されます。

`w1002.ura`：

```urayaha
ヤハ ヤハァ = ン・プ
ハァ？ ヤハァ == ン・プ ヤーッ
    ヤハ ヤハァ = ン・ル
    イヤッハー(ヤハァ)
ハァッ
```

実行：

```console
python -m urayaha run w1002.ura
```

stderr（終了コード 0）：

```text
[W1002] フゥン…

w1002.ura:3:5

        ヤハ ヤハァ = ン・ル
        ^^^^

「ヤハァ」、もういたみたい
```

stdout：

```text
ン・ル
```

### W1003 — UnreachableCode

見出しは「フゥン…」です。

ブロック内の `ハァーッ`、`ムリッ`、`イヤッ`、`ワァーッ！` の直後など、到達しない文に出ます。また、`もしかして` の対象と `ってこと？` のパターンの型が適合しない場合にも出ます。現在はすべての到達不能コードを検出するわけではなく、関数直下やトップレベル、catch 直下には同じ連続文の判定がありません。

`w1003.ura`：

```urayaha
ウ～ラ～ ン・プ == ン・プ ヤーッ
    ムリッ
    イヤッハー("ヤハ")
ハァッ
```

実行：

```console
python -m urayaha run w1003.ura
```

stderr（終了コード 0）：

```text
[W1003] フゥン…

w1003.ura:3:10

        イヤッハー("ヤハ")
                  ^

ここ、たどりつかないみたい
```

```text
[W1004] フゥン…

w1004.ura:1:1

    ヤハ ヤハァ = ……
    ^^^^

「ヤハァ」、なんの型かわからないみたい
```

```text
……
```

### W1006 — NotUrayahaEnough

見出しは「フゥン…」です。

`1` や `1.5` など、通常の 10 進数リテラルを使ったときの警告です。通常モードでは表示されません。`--strict-usagi`（別名 `--urayaha`）では表示され、次の run の例では実行前に停止します。文字列の中の数字は対象ではありません。

`w1006.ura`：

```urayaha
イヤッハー(1)
```

実行：

```console
python -m urayaha run w1006.ura --strict-usagi
```

stderr（終了コード 1）：

```text
[W1006] フゥン…

w1006.ura:1:7

    イヤッハー(1)
               ^

「1」って普通に喋ってない？(うさぎ数字だと「ン・プ」)

フゥン…

もうちょっとうさぎっぽくできるみたい
```

<!-- 要確認 -->

以下は、期待しやすい挙動と現行実装の差です。本文は現行実装に合わせています。

- `--debug` は内部名を追加しますが、「ほしかったもの / きたもの」を有効化するスイッチではありません。詳細は `Diagnostic.render` が notes の有無に応じて常に表示します。通常の警告の表示経路は内部名の表示を指定していません。
- E3005 NetworkError は仕様が要求するコードとして `CATALOG` に登録してありますが、v0.4 の通信 API は失敗を Result で返すため、実際に診断として表示される経路はありません。
- E3004 の実際の発行箇所には `runtime.py` のファイル import と `cli.py` の対象ファイル確認があります。標準ライブラリの `_fail` は診断ではなく失敗した Result を作ります。
- E9001 の再現は `.ura` プログラムではなく、`cli.py` の壊れたバイトコード読み込み経路です。終了コードは 1 でした。
- W1003 の到達不能判定は `checker.py` の `_body` を通る文列に限られます。関数直下の `ハァーッ` の後に文を書いても、この警告が出ないことを確認しました。

診断コードの名称と見出しは `urayaha/errors.py` の `CATALOG`、条件は `lexer.py`、`parser.py`、`checker.py`、`compiler.py`、`vm.py`、`stdlib.py` の失敗・警告・例外送出箇所で確認しました。CLI の表示と import の失敗については `cli.py` と `runtime.py` も確認しています。各コードの代表例を実行したもので、すべての発行箇所の個別分岐を実行したわけではありません。
