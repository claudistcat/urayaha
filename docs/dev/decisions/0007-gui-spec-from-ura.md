# ADR-0007: 画面の定義は `.ura` が返し、ホストは組み立てるだけにする

- 状態: 採用
- 日付: 2026-11-23
- 対象: `ウィーヤ`(GUI)、将来の GUI ホスト全般
- 関連: [ADR-0001](0001-event-loop-ownership.md)、[ADR-0004](0004-no-new-cries-for-api.md)、[ADR-0005](0005-os-open-not-launch.md)

## 決定

**GUI の「何を出すか」は `.ura` が Map で返す。** ホストはその Map を見て部品を
組み立て、押されたら `.ura` の関数を呼び戻すだけにする。

```
ウィーヤ.イヤッハー(画面の定義)   出して、閉じられるまで戻らない
ウィーヤ.ヤハ(なまえ, 文言)        部品の文言を書き換える
ウィーヤ.フゥン(なまえ)            部品の中身を取る
ウィーヤ.ハァ?()                   開いているか
ウィーヤ.イヤッ()                  閉じる
```

画面の定義のキーは `だいめい` `ぶひん` `まつ` `まつとき` だけ。部品の種類は
`もじ` `ボタン` `いれる` の 3 つから始める。

**ホスト固有の API は `.ura` 側に出さない。** 既定のバックエンドは Tkinter だが、
`.ura` からは Tk の名前も概念も見えない。ホストを差し替えるときは Python 側で
`stdlib.set_gui(バックエンド)` を呼ぶ(`set_opener`(ADR-0005)、`set_runner`
(ADR-0006)と同じ形)。

**イベントループはホストが持つ。** ADR-0001 のまま。`イヤッハー` は閉じられるまで
戻らない。定期実行は `まつ` / `まつとき` として画面の定義に書く。

## 理由

### 「裏の言語も URAYAHA」を成立させるため

Android 版で決めた分担(メモリ: ホスト側は器だけ)と同じ形にする。画面の文言・
部品の並び・押されたときの判断を `.ura` に置けば、ホストに残るのは「Map を見て
ウィジェットを作る」「コールバックを中継する」だけになる。ホスト言語に判断が
漏れた分だけ、この言語の存在理由が薄くなる。

### 宣言で済ませれば鳴き声を使わない

部品を 1 つずつ作る API(`ウィンドウを作る` `ラベルを足す` `配置する`)にすると、
操作ごとに語が必要になる。画面全体を 1 つの Map で渡す形なら、必要なのは
「出す」「書き換える」「取る」「開いているか」「閉じる」の 5 つで足り、すべて
既存の共通操作語に収まる。タイマーも `まつ` / `まつとき` というキーにしたので
語を使わない(ADR-0004 の方針どおり)。

### Tkinter を既定にする

Python に同梱されていて、Windows と Linux でそのまま動く。GUI のために外部
パッケージを入れさせると「インストールが容易」(v1.0 の条件)から遠ざかる。
見た目は素朴だが、最初の的(時計・ストップウォッチ・電卓・メモ帳)には足りる。

## 影響

- `ウィーヤ.イヤッハー` は閉じられるまで戻らないので、CLI として使うプログラムの
  途中に置くと止まって見える。出す前に `イヤッハー` で知らせるのが無難。
- 部品の種類を増やすときは「画面の定義のキー」を増やす形にする。新しい語は要らない。
- バックエンドを差し替えると、同じ `.ura` を別のホスト(Android など)で動かせる。
  テストでは窓を出さない偽のバックエンドを差し込んでいる。

## 却下した案

- **部品ごとに API を生やす** — 鳴き声が足りない(ADR-0004)。
- **イベントループを `.ura` 側に持たせる** — ADR-0001 の判断と衝突する。GUI ホストは
  自分でループを回したいので、譲れない。
- **外部の GUI ライブラリを既定にする** — 導入の手間が増える。必要になったら
  バックエンドとして足せる形にしてある。
