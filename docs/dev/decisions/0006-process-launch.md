# ADR-0006: コマンド起動の口を `ウロル.フゥン` の 2 引数として開ける

- 状態: 採用
- 日付: 2026-11-23
- 対象: v0.5 以降(`ウロル.フゥン`、`ウロル.ハァ?`)、ホストに載せるとき
- 関連: [ADR-0004](0004-no-new-cries-for-api.md)、[ADR-0005](0005-os-open-not-launch.md)

## 決定

**コマンドを起動して標準出力を取る口を開ける。** 置き場所は `ウロル` で、
引数の数で意味を分ける。

```
ウロル.フゥン(名前)              環境変数の取得（従来どおり）
ウロル.フゥン(コマンド, 引数List) 起動して待ち、標準出力を Result で返す
ウロル.ハァ?(コマンド名)          そのコマンドが使えるか（起動はしない）
```

**`ウロル.イヤッハー` の契約は変えない。** ADR-0005 の「開く対象を 1 つだけ
受け取り、コマンド名も引数配列も受け取らない」はそのまま残す。開くことと
起動することを別の口にする。

**シェルは通さない。** コマンド名と引数を別々に受け取り、文字列として連結しない。
引数に空白や `&&` が入っても解釈されない。

**ホストが差し替えられる。** `stdlib.set_runner(fn)` に argv を受け取って Result を
返す関数を渡すと、起動の実装を置き換えられる。起動させたくないホストは、失敗を
返す関数を渡して塞ぐ。`set_opener`(ADR-0005)と同じ形。

## 理由

### 「これだけで完結して書ける」を目標にすると、起動の口は要る

v0.5 時点の判断は「OS に開かせるだけで足りる」だった。しかし PC で使う道具を
URAYAHA だけで書こうとすると、`git` や `ffmpeg` のような既にあるコマンドを
呼べないことが壁になる。中に全部持つのは現実的ではない。

### それでも「開く」と混ぜない

`イヤッハー` は結果を待たず、出力も取らない。起動は終わるまで待ち、出力と
終了コードを返す。契約が違うものを同じ語に載せると、どちらの意味で呼ばれたか
戻り値から読めなくなる。ADR-0005 の判断自体は今も正しい。

### 鳴き声を増やさない

専用モジュールを立てれば読みやすいが、モジュール名には鳴き声が 1 語必要で、
ADR-0004 の「API のために鳴き声を新造しない」に反する。`フゥン`(取得)は
「出力を取得する」と読めるので、引数の数で分ければ語彙を消費しない。
`フゥ～ンフゥン.フゥン`(0 引数なら現在時刻、1〜2 引数なら parse)と同じ形。

### ホストで塞げるようにする

Android では他のアプリのプロセスを起動できない。処理系が無条件に
`subprocess` を呼ぶと、ホストに載せた瞬間に説明のつかない失敗になる。
差し替えのフックを置き、ホスト側が「できない」と答えられるようにする。

## 影響

- 標準出力は UTF-8 として読み、読めなければ OS の既定の文字コードで読み直す。
  Windows のコマンドは cp932 で書くものが多く、UTF-8 固定にすると化ける。
- 終了コードが 0 以外のときは失敗として扱い、理由に終了コードと標準エラー出力を
  入れる。終了コードそのものを取る API は、必要になってから考える。
- 待ち時間の上限は設けていない。終わらないコマンドを呼ぶと止まる。

## 却下した案

- **`ウロル.イヤッハー` の引数を増やす** — ADR-0005 の契約が崩れる。
- **専用モジュールを立てる** — 鳴き声を 1 語使う(ADR-0004)。将来、終了コードや
  標準入力の受け渡しまで欲しくなったら、そのときに名前を決めて昇格させる。
- **シェル経由(`shell=True`)にする** — 1 行で書けるが、引数の解釈をシェルに
  任せることになる。うさぎ語の文字列がそのまま解釈されるのは危ない。
