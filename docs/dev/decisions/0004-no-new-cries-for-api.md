# ADR-0004: API を増やすためだけに鳴き声を新造しない

- 状態: 採用
- 日付: 2026-09-14
- 対象: v0.5 以降の標準ライブラリ全般
- 関連: [ADR-0003](0003-regex-deferred.md)、[ロードマップ](../../roadmap.md)

## 決定

**この言語の語彙は、うさぎの実在発話に由来する。API を増やすために、それらしい
鳴き声を新造して予約語にすることはしない。**

v0.5 の文字列 API では substring(`フゥン`) / replace(`ヤハ`) / trim(`イヤッ`) /
find(`フゥー…ン?`) を追加するが、startsWith・endsWith・大文字小文字変換は
見送る。

## 理由

### 新造した鳴き声は説明できない

startsWith / endsWith に `プルャハ` / `プルヤッハ` を当てる案があった。しかし
これは字面が対になっているだけで、**「なぜ前方が濁らず後方が促音なのか」を
説明できない。** 既存の語彙はすべて実際のうさぎの発話か、`フゥン` `ヤハ`
`ハァ?` `イヤッ` `イヤッハー` `ン?` の共通操作語であり、字面合わせのための
造語はブランドを弱める。

### find に `フゥー…ン?` を採用した理由

「フゥー……ン？」は「探している・確認している」ニュアンスを持ち、戻り値
(見つかった位置、見つからなければ `……`)と意味が一致する。既存の `フゥン`
(取得)や `ハァ?`(確認)とも役割が重ならない。

### 大文字小文字変換は今すぐ必須と言えない

日本語中心の言語の CLI 基礎 stdlib として、今すぐ無いと困るとは言いにくい。

### substring と find があれば代替できる

startsWith / endsWith は `substring` と `find` を組み合わせて書ける。専用の
鳴き声を新造してまで今入れる理由がない。

## 保留したものの扱い

保留した機能は、v0.6 の dogfooding で実際に困ったら追加する。ロードマップ
§12(「作る → 困る → 仕様を追加する」)の適用例そのものである。
そのときは、字面合わせではない実在のうさぎ語かどうかを判断材料として使う。
